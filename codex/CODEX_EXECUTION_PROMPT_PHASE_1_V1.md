# 1. 冻结的产品 / 架构规则

这些规则不得自行修改。

## 1.1 前端产品入口

一级产品入口只有：

1. 新建任务
2. 任务列表
3. 研究对象

Research Scheme **存在**，但本阶段：

> 用户输入 Research Object + Research Goal → AI 生成 Research Scheme → 用户确认。

不要把 Research Scheme 实现成后台配置中心或独立一级产品。

## 1.2 Research Run 与 Task

用户创建的是：

`ResearchRun`

Task 是 Research Lead Agent 拆出来的执行单元。

默认：

> Plan First → Execute → Self-Correct → Replan Only When Necessary

Research Lead Agent 必须先形成完整 Initial Planned Task Graph，再交给 Runtime。

## 1.3 Self-Correction vs Replan

Self-Correction：

- Task 内部发生
- 不改变 Task Goal
- 不新增顶层 Task

Replan：

- Task 内无法解决
- Specialist Agent 只能提交 Replan Request
- 只有 Research Lead Agent 可以批准 Graph Mutation

## 1.4 金融硬门槛

必须在代码结构中显式体现：

> No unverified data enters formal financial reasoning.

以及：

> No deterministic financial number is authoritatively generated by the LLM.

正式金融数值必须通过 deterministic code / capability 产生。

## 1.5 Assurance 权限

Agent 对 execution 有自主权，但没有 assurance bypass 权限。

Review / Proof / Release 属于 Control Plane。

Langfuse 是横切 Observability，不是 Agent Tool。

## 1.6 Result Layer

A. Financial Report 是独立业务输出。

B. Financial Review View<br>
C. Execution Details

B/C 必须来自同一个 `CanonicalExecutionRecord`。
