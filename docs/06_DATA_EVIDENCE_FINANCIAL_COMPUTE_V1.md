# 06 — Data, Evidence & Financial Compute V1

[简体中文](06_DATA_EVIDENCE_FINANCIAL_COMPUTE_V1.zh-CN.md)

## 1. Two financial hard gates

> No unverified data enters formal financial reasoning.

> No deterministic financial number is authoritatively generated by the LLM.

## 2. Data flow

```text
Object Existing Data
      ↓ Freshness
Reusable ──────────┐
                   ↓
FMP / Other Source → Raw Snapshot
                   ↓
                Validate
                   ↓
                Normalize
                   ↓
             Conflict Resolve
                   ↓
           Accepted Evidence
              /         \
             ↓           ↓
          Agents     Financial Code
```

## 3. Data freshness

Example policies:

- company profile: slow-changing
- annual financials: refresh on new filing / restatement
- quarterly financials: refresh on new filing
- market price: short TTL
- news: short TTL
- peer multiples: short/medium TTL

MVP can use coarse TTL but schema must allow per-data-type policy.

## 4. Conflict handling

Do not equate source existence with truth.

Conflict checks:

- period mismatch
- TTM vs FY
- restatement
- currency
- units
- adjusted vs unadjusted
- source priority
- missingness

Output:

```text
ACCEPTED
CONFLICT
REJECTED
PARTIAL
```

## 5. Evidence package

Raw files go to Artifact Store.

DB keeps metadata + refs.

## 6. Financial statements

Canonical statement model should support:

- Income Statement
- Balance Sheet
- Cash Flow
- Annual / Quarterly
- Actual / Estimate
- provider source
- restatement version

## 7. Financial compute

Formal calculation:

```text
Accepted Evidence IDs
→ Calculation Inputs Snapshot
→ Capability Version
→ Deterministic Code
→ Output
→ Calculation Record
```

## 8. MVP calculations

Minimum useful set:

- Revenue Growth
- CAGR
- Gross Margin
- EBITDA Margin
- Contribution Margin if data available
- ROE
- Current Ratio
- Debt / Equity
- Free Cash Flow
- FCF Margin
- P/E
- EV / EBITDA
- SMA / RSI / MACD

### 8.1 Revenue Growth v1 reviewed semantics

`revenue_growth_v1` is exactly `(current_revenue - prior_revenue) / prior_revenue` with the
semantic precondition `prior_revenue > 0`. A zero or negative prior value fails closed with
`REVENUE_GROWTH_PRIOR_REVENUE_MUST_BE_POSITIVE`; it must never emit a growth percentage.

## 9. Forecasts

Forecast values must not be confused with actual values.

Every forecast must link:

```text
Assumption Set
Forecast Horizon
Run
Calculation / Model Version
```

## 10. AI judgment

LLM can output:

```text
judgment_type
claim
evidence_ids
calculation_ids
confidence
limitations
requires_review
```

Judgment is never silently converted to fact.
