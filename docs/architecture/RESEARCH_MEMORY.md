# Research Memory and incremental research

Released Research → typed Memory → Incremental Scheme → Refresh / Revalidate / Prevent → new released result → new Memory view → Base vs Current.

Only supported persisted items are represented. Verified metrics/claims require their actual proof status; release alone is not blanket verification. Unobserved categories remain NOT_OBSERVED. Zero reuse is a valid outcome.

Three identities must never be conflated:

| Field | Meaning |
| --- | --- |
| base_run_id | Prior RELEASED research used as knowledge baseline |
| scheme_id / fingerprint | Exact confirmed research intent |
| reexecution_of_run_id | Previous failed execution attempt, when applicable |

Fresh evidence, computation, review and report are produced for the new research. Historical approval is not inherited. Comparison uses exact logical keys such as formula, period, unit and claim type. Unmatched issues remain historical/new rather than being forced into an invented equivalence.

The accepted current object has View v2 with one verified metric, one verified claim and one resolved period issue, compared to retained v1. This loop is implemented; full Evaluation/POT is separate future work.

Historical read navigation does not trigger a Memory write. Existing active incremental nonterminal → RELEASED observation retains the explicit publication trigger. Failed or repeated terminal projections do not create a new view merely by being opened.
