## Shared full-stack invariants

1. The business chain is `Object → Research Definition → Goal → Scheme → Run → Execution → LLM Call → Claim → Metric/Calculation → Evidence → Task → Review → Proof → Artifact`; every applicable hop is queryable and no layer synthesizes identity.
2. Backend state, event stream, persisted rows and visible UI must agree at a named revision/watermark. Replay, refresh and process restart must converge on the same terminal projection.
3. Provider/model is selected before Run admission and locked during that Run. No silent mid-Run failover is allowed. Any later controlled failover needs immutable `providerBefore`, `providerAfter`, `modelBefore`, `modelAfter`, `taskId`, `attemptId`, `failureReason`, `timestamp`, and `policyId` provenance.
4. FMP data follows raw receipt → validation → normalization → conflict handling → accepted evidence. Missing or conflicting data cannot become a released fact by UI inference.
5. HTML is required. PDF is optional and independent. Every artifact GET repeats identity, state and integrity checks; a reference is never a bearer token and no failure may leak bytes or raw storage paths.
6. Langfuse evidence is fail-open for observability but never authoritative for business success; secrets, prompts, chain-of-thought, provider bodies and database internals are excluded.

## Failure and recovery matrix

| Failure class | Required behavior | Recovery proof |
|---|---|---|
| Network/SSE interruption | Preserve committed business state; reconnect using the bound cursor family; reject ahead/foreign cursors. | Same projection hash after replay, bounded backoff, no duplicate effective event. |
| Browser refresh/navigation | Rehydrate from backend authority; preserve only valid route/drawer/focus/scroll context. | Fresh browser context and back/forward evidence. |
| API response loss/concurrency | Idempotency returns the same admitted Run and never creates a second effective start. | Idempotency fingerprint plus database cardinality. |
| Provider failure | Record safe failure and locked provider/model; do not silently switch provider. | Provider-attempt ledger and exactly one terminal outcome. |
| Data conflict | Quarantine or explicitly resolve before acceptance/release. | Raw and normalized hashes, conflict decision and Review closure. |
| Artifact absence/tamper | HTML/PDF slots fail independently; explicit availability; zero bytes on denial/integrity failure. | Metadata/content/hash ledger and negative byte count. |

## Aggregation rule

The Phase 4 product numerator and denominator include only `SCENE-01..04`. A Phase 4 aggregate is PASS only when all four have executed PASS receipts and all applicable blocking technical gates have PASS receipts. `SCENE-05..06` stay visible as design coverage with `result=null`; converting null to PASS, FAIL, BLOCKED, zero, or an omitted row is a release-integrity failure.
