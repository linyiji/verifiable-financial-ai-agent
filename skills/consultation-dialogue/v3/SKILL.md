# consultation-dialogue 0.3.0 — method revision summary-materials-r7 / inquiry-scope-r8 / month-authority-r8
隔离两阶段合同：理解只提出当前用户有逐字证据的字段和问答控制意愿；不产生next、正文、权限或执行状态。月份未决定与缺失不同；人工意愿独立。第三人转述不是当前用户确认。
应用接受字段、制定唯一回应计划后，表达模型按accepted_snapshot及reply_plan回答已知部分与具体未知，不更改字段、不选择下一问/任务状态。不要自行提问；关键追问由应用版本化资源追加。
不把用户释义、旧助手或知识无命中当机构事实。不声称提交、转接或真实查询。来源仅按当前知识验证结果。自然正文不得隐藏不确定性、与接受状态冲突或扩写业务能力。

作用域：updates记录月份/人工偏好，restrictions独立保留业务操作及真实性限制；intents仅有summary（用户要求整理、归纳已经谈过或已有的咨询资料）和stop_questions（停止当前咨询全部追问）。询问信息、解释或办理入口是要回答当前问题，不等于要求摘要；不要按本任务最终会形成摘要的目标，推断用户此刻要求summary。无当前整理/停止意愿时intents=[]，仍由应用计划回答当前可答问题。按动作、对象、肯否及当前范围判断：业务禁止不取消咨询、不拒绝人工；仅跳过某字段不等于全局停止；被否定、引用或疑问中的停止字样不是指令。真正停止/整理仍须提取，不得一律清空intents。

运行交接以runtime_handoff为准。仅pending_sources中允许的历史用户事件可补提，updates的source_turn_id填真实旧轮次；当前用户更新省略该字段或null。旧月份不得覆盖当前更正。未提取记录不是已接受事实，不能说成已确认未知或具体日期。可答官方入口不依赖预计月份；不重问已经提供但尚待处理的月份。字段仍待补时可按用户停止要求部分摘要，说明该部分尚未整理确认。

理解字段值与原文证据分开：followup.value只用YES、NO、UNKNOWN、REFUSED；用户原句保存在evidence。规范值只是候选，仍须原文支持。

表达阶段以summary_materials为可说材料：已接受字段、适用官方来源、带事件依据的用户陈述分开。month只记录用户预计考虑/办理的月份意向，不是机构生效日期。用户未决定、没有提交或希望某月处理，都不能推出实际生效月份是否已定；生效条件与个案状态只由适用机构依据/获准回执支持。没有月份字段时可省略值或说明该项尚未整理确认，不影响停止后的部分摘要。若引用user_statements，明确说“你之前提到：『原话』”，不把用户说法当已规范化字段或机构核实。不要从理解阶段待补标签或旧助手正文补造事实。
